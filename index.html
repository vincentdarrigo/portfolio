Project study · Client work

IMRAface

In production · private Request a demo

The software layer behind a statewide education review program.

IMRAface runs the operational side of a statewide instructional-materials review: assignments, approvals, support, and the data that ties them together for 1,500+ reviewers. I lead its development at Safal Partners. The work spans several data services, so most of the engineering is about keeping them in sync without losing anyone's work.

  • Python
  • Flask
  • FastAPI
  • PostgreSQL
  • SQLite
  • Alembic
  • Smartsheet API
  • Google Workspace APIs
  • Anthropic API

Reviewers supported

1,500+

Statewide review program

247

Synced per unattended run

90+

Workbooks, with no one watching

What I built

Scope

Multi-role web application

A real application in front of the spreadsheets, with views scoped to each kind of user, approval workflows, and automated operations.

The hard part

Each role sees and changes only what it should, while the underlying data services stay in step.

Reconvene workflows, built mid-cycle

Built quickly during a live review cycle: six data sources reconciled into 247 team workbooks, with two-way sync.

The hard part

Two-way sync means two writers. Safeguards stop a stale copy from overwriting newer edits.

Unattended synchronization

Runs across 90+ workbooks per pass with no one watching.

The hard part

Rate limits, partial failures, and hand-entered data. The sync backs off automatically, reports structured health diagnostics, keeps bulk writes reversible, and protects what users typed.

Production data repair

Found 45 corrupted cells across 17 production workbooks and restored them from cloud revision history.

The hard part

Fixing the cells wasn't enough. I traced the corruption to a defect in the template the workbooks came from, and fixed that to prevent a repeat.

Human-in-the-loop support agent

An LLM agent classifies incoming support tickets, researches each one, and queues a proposed resolution.

The hard part

The agent proposes and a person approves. No system action runs until someone signs off.

Database-backed next version

A more scalable platform on PostgreSQL, with versioned migrations and automated tests.

Outcome

Demos of the working platform helped stakeholders reconsider their plans for additional review capabilities.

How it gets built

I use Claude and other coding agents to implement features. My part is turning shifting requirements into precise instructions, then personally validating UI behavior, edge cases, and the seams between frontend and backend before anything reaches reviewers.

  • PrivateIMRAface is a client system, so there's no public link and no client data on this site.
  • On requestReview Portal is a synthetic-data copy of the review workflow: 1,551 fictional reviewers, 398 programs, and 57 publishers, with data sync, email, and SMS switched off in demo mode. Ask for a walkthrough.
  • InterviewHappy to walk through the architecture, the sync safeguards, and the agent's approval flow on a call.

Project study · AI product

Thinkio

Live · teacher accounts Visit Thinkio ↗

A classroom platform that grades how students work with AI, not just what they turn in.

Students write with io, a Socratic GPT-4o tutor that coaches instead of handing over answers. Thinkio pays attention to how each student works with it. Did they set a goal first, ask clearly, check what came back, and stay honest about what was theirs? Those habits become the student's Learning DNA.

  • Python
  • FastAPI
  • React
  • TypeScript
  • PostgreSQL
  • WebSockets
  • GPT-4o
  • GPT-4o Vision
  • DALL·E 3

Grades recorded without a teacher

What I built

Scope

io, the Socratic tutor

A GPT-4o tutor that asks guiding questions instead of writing the work for the student.

Learning DNA

Four strands and twelve traits, each tiered from evidence in the student's own tutoring transcript.

The hard part

Grading behavior, not vibes. Every trait is defined by observable actions a teacher can point to.

Teacher-in-the-loop calibration

On each submission, one GPT-4o call drafts the grade and scans the tutoring transcript for trait evidence.

The boundary

The model only suggests. Nothing reaches a student's record until a teacher confirms it.

Curriculum Studio and classroom tools

Turns a PDF into standards-aligned lessons with GPT-4o Vision. Also includes a live classroom game mode over WebSockets, DALL·E 3 mascots, and a cost tracker for every AI call.

The hard part: precision

An early QA sample found that 4 of 5 evidence suggestions were false positives. The model was matching a student's general vibe instead of observable behavior. I rewrote the prompt to ground each suggestion in the trait's full checklist of observable elements. Either way, a teacher confirms every result before it counts.

I Spy AI · I Spy A Pie

Live Play live ↗

One real-world scavenger-hunt engine, two different games.

Pick a city and the AI builds a mission around real places you can visit. In I Spy AI you're a field agent guided by K.A.I.T. through a tech-espionage story. In I Spy A Pie it's an underground pizza-critic tour: three-layer, Jeopardy-style clues lead to real local spots, each scored with a One Bite Score when you find it.

Project study · AI game

Anytime AI Trivia

Live Play live ↗

Type any topic and get a playable multiplayer trivia game.

Players join a room and pick a topic, and the AI builds a full game on the spot, with synced timers, a shared scoreboard, and four question types: multiple choice, free text, closest number, and drag to rank.

  • Python
  • FastAPI
  • WebSockets
  • GPT-4o
  • JavaScript

Question types

4

Plus deliberate trick questions

Trick questions per game

1–2

Written with a false premise on purpose

Challenges per player

2

To appeal an AI ruling in front of the room

What I built

Scope

Live rooms

FastAPI and WebSockets keep every player on the same question, the same timer, and the same scoreboard.

Trick questions

The AI deliberately writes one or two questions whose premise is false. Spot one and you earn bonus points.

Worth saying

This is a game mechanic, not fact-checking. Catching a planted false premise is a different problem from validating every answer.

Challenge AI

Disagree with a ruling? Type your argument. The AI rules with its reasoning, and the verdict goes out to the whole room.

Question bank

Every generated question is saved to a growing bank, so AI output becomes a reusable asset instead of a one-shot call.

What you can check

  • Livetrivia-app-qgwf.onrender.com. Host a game solo to see a full round. The first load can take up to a minute.

Method

AI-assisted. Personally verified.

Coding agents write a lot of my code. I'm accountable for all of it. Here's how that works.

  1. 01

    Pin down the real requirement

    Requirements shift, especially mid-cycle. I turn them into precise, testable instructions before any code gets written.

    Clear instructions

  2. 02

    Direct the coding agents

    Claude Code and Codex implement from those instructions. I own the architecture, the data model, and the review.

    Working code, fast

  3. 03

    Verify it myself

    I test each user role, the edge cases that matter, and the failure paths myself, then chase down problems at the seams between frontend and backend. The agent doesn't get the last word.

    Tested behavior

  4. 04

    Build for the bad day

    Retries with backoff, health diagnostics, reversible bulk writes, conflict safeguards, and logs that explain what happened.

    Systems that recover
