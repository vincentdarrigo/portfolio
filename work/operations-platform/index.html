Case study · Client work

Proprietary Operations & Data Platform

Production · private Ask about this work

An internal multi-role application behind a large, multi-stakeholder operational program.

After months spent connecting and automating existing workflows, I saw that the operation needed a real application to keep growing. I proposed and initiated the platform, then led the work of connecting the systems and refining it with the people who use it. Today it handles approvals, task routing, support, and reporting, and keeps several existing business systems in step through Python services and APIs. A newer database-backed generation, built on PostgreSQL, has been built and demonstrated; production still runs on the original platform.

Initiated it · technical lead

Status

Stack
Production: Python, FastAPI, SQLAlchemy, SQLite, REST APIs. Next generation: PostgreSQL.

The problem

The program's work was spread across several business systems, joined by manual handoffs and standalone scripts. The rules changed mid-cycle, the workload was large, and the people doing the work couldn't stop while the software caught up.

What I owned

  • Proposing the application in the first place, after building the workflow automations it replaced.
  • Turning shifting stakeholder requirements into workflows and detailed task instructions for coding agents.
  • Designing the data flows, integrations, and the schema for the database-backed version.
  • Directing Claude and other coding agents, then reviewing what they produced.
  • Validating UI behavior and edge cases in the browser, and troubleshooting frontend and backend interactions.
  • Deciding when a change was ready to reach the people who depend on it.

The hard parts

Engineering decisions

Mid-cycle reconciliation workflow

Built during a live cycle: distinct data sources reconciled into team working files, with updates flowing both ways.

The decision

Two-way sync means two writers. The workflow had to keep team files and the central record consistent while people kept working in them.

Unattended synchronization

Scheduled synchronization across many working files, with no one watching.

The decision

Treat rate limits and partial API failures as normal. The sync backs off and retries, reports structured health information, and preserves what people entered by hand. Bulk changes run as a dry run first, and repairs back up each file before touching it.

Permission-aware interfaces

Role-specific views in one application, replacing direct work in shared spreadsheets.

The decision

Each role sees and changes only what it should, while the systems underneath stay in sync.

Human-in-the-loop AI support workflow

A workflow designed so that a model classifies and researches incoming support requests and prepares a proposed action.

The boundary

The model proposes. A person approves before anything consequential changes.

Status

Designed and in development. I'm not presenting it as a production feature.

Production data-integrity repair

Diagnosed a live data-integrity problem and reconstructed the affected records from the source system's revision history.

The decision

Fixing the records wasn't enough. I traced the problem to a defect in the upstream template and fixed it there, so the same failure is less likely to come back.

Database-backed next generation

PostgreSQL with relational models, versioned migrations, and automated tests, moving toward managed integrations and centralized data-access boundaries.

Status

Built and demonstrated to stakeholders. Production still runs on the original platform.

Validation

I personally validate UI behavior and edge cases in the browser, and troubleshoot the interactions between frontend and backend when something's off. The data-integrity repair is the clearest example of the principle: restore the records, then find and fix what caused them to break.

Outcome

A working production capability the program relies on, and specific problems solved along the way: a reconciliation workflow delivered in the middle of a live cycle, synchronization that recovers from routine API failures without losing human edits, and a data defect fixed at its source. Demonstrations of the newer generation helped establish confidence in the platform and opened discussions about expanding its responsibilities.
